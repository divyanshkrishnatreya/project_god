# Continuity Rules - Leela.exe

## Purpose
This file defines how canon is preserved across pages, chapters, prompts, and revisions.

## Canon Priority Order
1. Explicit user-approved retcons or corrections
2. Approved final page images and page-specific correction notes
3. `continuity/chapter_memory.md`
4. `continuity/series_memory.md`
5. Character sheets in `characters/`
6. Lore documents in `lore/`
7. Style documents in `style/`
8. Unapproved exploratory prompt notes

If two sources conflict, the higher source wins unless the user says otherwise.

## Always Check Before Generating A New Page
1. Current chapter memory
2. Series memory
3. All characters appearing on the page
4. Relevant lore rules
5. Style rules
6. Current emotional trajectory

## Series Format Rules
1. Each Dashavatar gets one chapter only.
2. Each chapter is exactly 10 pages.
3. Each chapter must complete that avatar's full dramatic arc inside those 10 pages.
4. Final pages should land on closure, resolution, or cycle transition, not on a dependent "to be continued" for the same avatar's unresolved plot.
5. Cliffhangers are allowed only if the avatar's core conflict is already resolved and the next chapter is beginning a new avatar cycle.

## Continuity Categories To Track
### Visual
- character face shape
- hairstyle
- costume details
- jewelry and props
- body scale
- injuries, wetness, mud, tears, blood, exhaustion
- weather and lighting

### Spatial
- location
- geography
- entry and exit directions
- relative distance between characters
- water height and terrain changes

### Narrative
- what each character knows
- what revelation level has been reached
- promises, warnings, and instructions already given
- unresolved questions

### Emotional
- current mood per character
- trust level between characters
- whether a scene should breathe, escalate, or release tension

### Symbolic
- repeated motifs
- sacred signs already introduced
- visual metaphors that should recur consistently

## Style Drift Detection
Flag a page if it drifts toward:
- a different facial design for a recurring character
- inconsistent costume logic
- flatter or more generic lighting than prior pages
- missing water/sky detail in a water-driven chapter
- sci-fi imagery overpowering mythic tone in mortal-world scenes
- emotional acting that contradicts previous beats

## Special Continuity Rule For Admin Scenes
Modern interface elements, keyboards, monitors, and menu text are canon only in explicit Vaikuntha admin-space scenes or clearly framed meta-prologue scenes. Do not let this visual language spill casually into mortal mythic reality.

## Update Protocol After Each Approved Page
1. Record the page number and status.
2. Summarize the page objective and final beat.
3. Log what changed physically, emotionally, and narratively.
4. Add any newly locked design details.
5. Add carry-forward notes for the next page.

## Correction Protocol For Uploaded Pages
When a page image is uploaded:
1. compare it against current chapter memory
2. check character model consistency
3. check emotional continuity
4. check environment continuity
5. identify drift, contradictions, or ambiguity
6. recommend fixes before generating the next page

## Hard Rules
1. Never ignore a previously established prop, injury, scale change, or weather shift.
2. Do not escalate divine revelation faster than the chapter memory allows.
3. If a design evolves, update the character file and chapter memory immediately after approval.
4. If continuity is uncertain, pause and resolve the uncertainty before building on it.
5. Track remaining page budget at all times so the chapter can still conclude cleanly by page 10.

## Recurring Production Habit
Treat every page like an animation keyframe with memory. The page is not isolated art. It is part of a sequence.
